# 问题链：Agentic Recommender Systems 综述

## Q1. 领域为什么存在
- 传统推荐：给定用户和上下文，输出排序列表。
- 限制：难支持复杂多步目标，如旅行规划、约束推理、迭代调整。
- 目标：从“排序模型”变成“追求目标的系统”，能规划、调工具、维护记忆、迭代推荐。
- 综述声称缺口：agentic 用法不一致，缺统一自主性视角；系统发展速度快于评估手段的更新

## Q2. 怎么分类
- 双轴：角色 × 自主性等级。
- 角色：agent-assisted、agent-as-recommender、agent-as-simulator。
- 等级：L2 检索辅助、L3 工具编排、L4 单 agent 规划、L5 多 agent 协调。
- 组件：profile、memory、tool、workflow、optimization。

## Q3. 每类方法解决了什么，又牺牲了什么
- 辅助型：增强检索/意图/解释，但仍依赖经典推荐，自主性有限。
- 替代型：agent 端到端决策，能力强，但成本高、幻觉、协调难。
- 仿真型：可生成反馈做评估，但仿真器可能与用户显示决策不一致。
- 评估：从排序指标扩到轨迹指标，但轨迹评估、贡献归因、仿真校准仍未解决。

## Q5. 可能的小方向

### 方向 1：终身用户建模
- 缺口：建模缺口。
- 问题：怎么区分长期偏好和短期行为，持续更新还不遗忘？
- 范围：跨会话推荐；MovieLens/Amazon/Lastfm；RecBole/Agent4Rec。
- 方法：分层记忆 + 检索增强偏好摘要 + 身份一致性约束。
- 评估：长期 HR/NDCG、遗忘率、身份一致性；对照无记忆/全历史。
- 风险：长期偏好和短期行为真的可分吗？

### 方向 2：轨迹级评估
- 缺口：评价缺口。
- 问题：怎么记录完整轨迹，量化 tool/memory/planning/multi-agent 的贡献？
- 范围：AgentRecBench、RecoWorld、RecAgent、Agent4Rec。
- 方法：轨迹格式 τ；指标向量 m(τ)；角色消融；LLM-as-judge 校准。
- 评估：轨迹指标与最终指标、在线 A/B、人类判断的相关性。
- 风险：LLM judge 不稳定；仿真器校准不够。

## 一句话总结
从静态排序到目标导向 agent → 用角色×自主性分类 → 每类在能力、成本、评估上各有取舍 → 回原文验证关键论断 → 可能切入方向：终身用户建模、轨迹级评估。
